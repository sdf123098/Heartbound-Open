# Heartbound 26.1.2 第一人称场景相机与玩家模型修复计划

## 一、目标

修复 26.1.2 中正式场景及场景准备阶段的相机、玩家模型和床上定位问题，使行为尽量恢复到 1.21.1 的设计，并在必要时改善原版取景。

最终需要同时满足：

1. 点击场景按钮但尚未与女孩接触时，不渲染替代玩家模型，不启用 `boyCam` 场景相机。
2. 正式进入场景后，玩家实体及必要身体部件存在，旁观视角可以看到完整、正确的双方模型。
3. 第一人称下玩家头部或躯干不遮住主要画面，但不能通过彻底隐藏玩家模型来掩盖问题。
4. 玩家生殖器、手臂和必要躯干部件正确连接到骨架，不再四分五裂、错位或消失。
5. Jenny doggy、Ellie carry/faceFuck 等动作的关键交互区域处于合理视野内。
6. 床上场景的女孩和玩家固定在床锚点，不浮空、不漂移，结束后不会落到地面以下。
7. 非床场景不发生整体位置偏移。

## 二、已确认事实

1. 1.21.1 使用动画模型中的 `boyCam` 骨骼作为第一人称相机位置。
2. 1.21.1 在模型渲染后读取 `GeoBone.getWorldPosition()`，随后在 `CameraMixin` 中直接覆盖相机世界坐标。
3. 1.21.1 只在第一人称且 `girl.isHavingSex()` 为真时应用女孩场景相机。
4. 1.21.1 不按场景把玩家躯干设为透明，也不通过完全隐藏玩家模型解决遮挡。
5. 1.21.1 与 26.1.2 的八份女孩动画 JSON 哈希完全一致，Jenny 和 Ellie 的模型文件也一致。
6. Jenny 的 doggy 动画没有单独移动 `boyCam`；相机主要继承玩家 `Head2` 骨骼的动画变换。
7. GeckoLib 5 的 `RenderUtil.providePositionsToListeners` 可提供骨骼世界坐标，其数学目标与 GeckoLib 4 的跟踪矩阵相同，但仍需通过运行时数据验证移植后的实际结果。
8. 当前 26.1.2 使用 `isSceneActive()` 启用相机，范围比 1.21.1 的 `isHavingSex()` 更大，可能导致准备阶段提前启用场景相机。
9. 当前工作区包含第一人称头部隐藏和躯干透明的临时处理；该处理不是最终方案。

## 三、修复原则

1. 先恢复 1.21.1 的相机和渲染语义，再做有证据的场景取景优化。
2. 相机问题优先调整 `boyCam` 世界坐标或场景阶段偏移，不优先隐藏模型。
3. 第一人称可隐藏会包住相机的头部几何，但玩家骨架、手、躯干和生殖器仍需参与动画与渲染。
4. 第一人称和 F4 旁观视角使用同一套骨骼动画；仅可见性策略不同，不能生成两套位置逻辑。
5. 床锚点只控制场景实体的世界位置和朝向，不应与第一人称相机偏移相互补偿。
6. 每一阶段都先验证，再进入下一阶段，避免相机、模型和锚点问题相互掩盖。

## 四、实施步骤

### 阶段 1：建立可重复的测试矩阵

- 固定测试世界、床朝向、玩家皮肤类型和女孩位置。
- 为每个场景记录：女孩实体位置、场景阶段、`boyCam` 世界坐标、`boyCam - girl.position()` 相对坐标、玩家乘坐状态和相机最终坐标。
- 至少覆盖以下重点动作：
  - Jenny：doggy intro、slow、fast1、fast2、cum，以及床上准备阶段。
  - Ellie：carry intro、slow、fast、cum；missionary；cowgirl。
  - Bia/Coppie：anal 和 prone doggy。
  - Slime/Kobold：blowjob、doggy 或 anal。
  - Aly：sex、blowjob、nelson。
- 分别截取第一人称和 F4 旁观视角，用相同动画时间点进行比较。
- 如可以运行 1.21.1，则记录同一场景的相对相机坐标，作为基准数据。

### 阶段 2：恢复 1.21.1 的相机启用条件

- 将女孩场景相机的判断恢复为正式接触阶段，即与 1.21.1 一致地使用 `isHavingSex()`。
- 场景准备阶段清理旧的 `clientBoyCamPos` 和跟踪实体 ID，防止上一场景坐标残留。
- 确认点击按钮、女孩等待玩家靠近、女孩走向床等阶段均使用正常玩家第一人称相机。
- 单独检查变身玩家场景，避免修改女孩场景条件时破坏 `girlCam`/`boyCam` 的另一套乘坐关系。

### 阶段 3：验证并修正 GeckoLib 5 的 `boyCam` 世界坐标

- 保留 GeckoLib 5 的逐骨回调方案，但输出受控的调试数据，与 1.21.1 的计算结果逐项对照。
- 验证回调发生在目标骨骼枢轴处，而不是 `translateAwayFromPivotPoint` 之后。
- 验证计算包含完整父骨链，特别是 `steve -> Torso2 -> Head2 -> boyCam`。
- 验证模型根旋转、实体朝向、床朝向和实体世界位置只应用一次。
- 验证相机坐标与当前渲染帧使用相同的动画快照，排除一帧延迟或上一姿势残留。
- 若官方监听器结果与 1.21.1 基准不一致，使用明确的兼容计算还原：
  - 当前骨骼枢轴矩阵；
  - 乘以模型根矩阵的逆矩阵；
  - 加上女孩实体世界坐标；
  - 不重复叠加实体朝向或渲染平移。
- 坐标验证完成后删除高频调试日志，仅保留异常值保护。

### 阶段 4：恢复正确的玩家模型渲染

- 移除按场景设置躯干透明度的临时规则。
- 正式场景中始终保留玩家替代模型的骨架遍历，使手、身体和生殖器共享同一父骨变换。
- 第一人称只处理真正包住相机的头部几何；不得跳过 `Head2` 子骨骼的动画传播。
- F4 旁观视角完整渲染头部、躯干、四肢和生殖器。
- 检查 Steve/Alex 手臂分支：只渲染与当前皮肤模型匹配的一组手臂，不能错误跳过共同父骨。
- 检查自定义子树递归：每个子骨必须成对执行入栈、骨骼变换、`translateAwayFromPivotPoint`、递归和出栈。
- 检查皮肤层与生殖器纹理层是否复用完全相同的骨骼姿势，避免重复变换。

### 阶段 5：逐场景修正第一人称构图

- 在世界坐标计算已经与 1.21.1 一致后，再判断是否需要改善原版取景。
- 优先修改动画中的 `boyCam` 关键帧；只有无法安全修改资源时，才在代码中加入按女孩、场景和阶段划分的相机局部偏移。
- 偏移必须在女孩/模型局部坐标系中定义，再随场景朝向旋转到世界坐标，不能直接写死世界 X/Z。
- 优先处理：
  - Ellie carry/faceFuck：相机适当远离或抬高，避免玩家胸腹遮挡女孩头部和关键交互区域。
  - Jenny doggy fast1/fast2：调整前后、高度或横向位置，使双方关键区域同时进入画面。
  - Jenny 床上 doggy：保证床面、双方身体和关键区域的相对关系可见。
- 对其他女孩执行同类遮挡扫描，重点检查 anal、doggy、cowgirl、missionary、sex、nelson。
- 相机朝向默认继续由玩家控制；只有位置修正后仍无法得到稳定取景的姿势，才评估有限的朝向引导。
- 不在同一轮同时大幅修改相机位置和朝向，便于定位回归来源。

### 阶段 6：独立验证床锚点与退出位置

- 检查床锚点是否由床方块中心、床头方向和场景预设偏移唯一计算。
- 服务端固定场景实体位置和朝向，客户端只负责插值及渲染，不反向改写锚点。
- 玩家乘坐后使用 `boyCam`/乘客骨骼同步位置，但不得累计相对偏移。
- 每个循环阶段验证女孩和玩家不会逐帧漂移。
- 结束、跳过、女孩被移除和玩家断线等退出路径统一恢复安全地面位置。
- 分别测试四个床朝向、床边障碍物和非完整地面。

### 阶段 7：回归测试与干净构建

- 执行 Gradle clean build，确保产物不包含旧 class 或旧资源。
- 检查编译警告、Mixin 注入目标和运行日志中的异常。
- 使用新 JAR 完整执行测试矩阵，不复用旧 JAR。
- 记录 JAR 文件名、绝对路径、大小、构建时间和 SHA-256。
- 至少完成以下回归：
  - 点击按钮但未接触：无替代玩家模型、无错误场景相机。
  - 正式场景第一人称：相机正确，玩家模型不遮满视野，必要身体部件可见。
  - F4 旁观：双方模型完整且不重叠、不消失。
  - 床上：双方固定、无浮空、无乱飘。
  - 非床：无整体高度或水平偏移。
  - 退出：玩家回到安全地面，不落入地下。

## 六、验收标准

修复只有在下列条件全部满足时才算完成：

1. 准备阶段没有提前出现玩家替代模型或场景相机。
2. 正式场景第一人称与 F4 旁观视角都存在玩家模型。
3. 第一人称不会被头部或躯干大面积遮挡。
4. 手臂、身体和生殖器没有断裂、漂移、重复变换或错误隐藏。
5. Jenny doggy 和 Ellie carry 的重点动作具有清晰、稳定的构图。
6. 其他女孩的同类姿势经过逐项检查，没有明显视野盲区。
7. 床上与非床场景均无浮空、乱飘、重叠和地下退出问题。
8. 干净构建成功，并提供可测试 JAR 与 SHA-256。

## 七、回退策略

- 每个阶段单独提交或保留独立补丁，避免把相机、模型和床锚点修改混在一个不可拆分的变更中。
- 若场景取景优化产生回归，先回退具体场景的 `boyCam` 偏移，不回退已经验证正确的世界坐标计算。
- 若玩家可见性修改产生回归，恢复 1.21.1 的完整模型渲染语义，不使用全模型隐藏作为长期方案。
- 保留最后一个已验证 JAR 的哈希，便于测试结果对照。
