## 四、Bug 3：装备栏紫黑方块（已修复）

**根因**：26.1 删除了 1.21.1 时代的 `item/empty_armor_slot_*` 纹理。26.1 的 `AbstractContainerScreen` 用 `blitSprite(getNoItemIcon())` 渲染空槽图标（sprite 系统），模组传的旧路径不存在 → 紫黑。

**修复**（`GirlInventoryScreenHandler.java`）：6 个槽位图标常量从 `Identifier.withDefaultNamespace("item/empty_armor_slot_*")` 改为 `Identifier.fromNamespaceAndPath("minecraft", "container/slot/*")`——与 vanilla `InventoryMenu` 一致（javap 反编译确认 `InventoryMenu.class` 用 `container/slot/helmet` 等路径）。mod 自己的 sprite（`textures/gui/sprites/...`）自动进 gui atlas，无需 atlases/gui.json。

## 五、Bug 2：射精提示无边框和文字（根因已定位）

**日志证据（latest-10.log）**：

## 六、Bug 1：床场景玩家错位（WIP4 根治，本次重点）

### 日志铁证（WIP3 探针，latest-11.log）

- `passengerPos ... bonePos=(0,0,0) isZero=true`（INTRO/HAVING_SEX 全程）→ 乘客永远走 `passengerYOffset=-1.0F` 兜底，钉在 girl+1.0
- `cam ... havingSex=true boyCam=null tracked=-1` 贯穿全程 → boyCam 位置监听从未成功
- `adjustBones ... boneFound=true posTicket=有值` → 监听注册成功、POSITION ticket 有值，但**回调从未被触发**（监听调用计数=0）
- `steveLayer run ... pose=-2.296E-1 0.000E+0 9.733E-1 6.712E-1` → steve 层 pose 平移 ≈(0.671, 0.643, 0.591)，**模型局部系**（女孩世界坐标是 3.5/-60/13.5）
- `playerRender=0` → 本地玩家抑制 mixin 从未触发（26.1 第一人称身体渲染路径与 GL5 泛型 submit 重载有关，不作为兜底依赖）

### 根因（GL5 5.5.2，geckolib-fabric-26.1.2-5.5.2）

1. `submitPerBoneRenderTasks` 把 pose 栈重置为捕获的**模型局部** pose（实测平移 ~0.6 非世界系）；自定义层 `poseStack.last().set(pose)` 把世界系 pose 整体替换 → **steve 替身形象渲染到错误位置，第一人称看到自己模型与女孩重叠**
2. `RenderUtil.providePositionsToListeners` 依赖被破坏的 pass pose 上下文（`getModelRenderMatrixState()` 遇 identity 抛 `IllegalStateException`）→ **per-bone 位置监听从不触发** → bonePos 恒 0 → 乘客钉在 girl+1.0（床场景错位）

### 修复（WIP4）

**A. `BoneOverrideRenderLayer.java`**：`poseStack.last().set(pose)` → `poseStack.last().set(passInfo.getPreRenderMatrixPose())` + `poseStack.last().pose().mul(pose.pose())`（世界变换 × 局部 pose = 正确世界位置）。

**B. `AbstractGirlRenderer.java`**：在 `adjustModelBonesForRender` 里用与 GL5 相同的逐骨矩阵数学手动计算 boyCam 世界位置：
- 每骨变换：`T(-snap/16, X取反) · T(pivot/16) · Rz·Ry·Rx(baseRot+snapRot, 弧度) · S · T(-pivot/16)`
- 从模型根骨（parent==null）累乘到目标骨，identity 起点 → 目标骨相对模型原点的偏移（格）
- 世界位置 = 实体位置 + 模型局部链（模型原点 = 实体位置，GL5 无 getModelOffset 覆写点）
- 驱动 `clientBoyCamPos`（相机吸附）+ 发 `BonePosSyncC2SPacket`（乘客位置）
- 仅当 `Minecraft.getInstance().player.getVehicle() == animatable` 时写入（防 GUI 预览克隆体覆盖）

**关键验证**：JOML `Matrix4f.toString()` 按列打印（每行 = 一列，平移在每行第 4 个元素 = m30/m31/m32）；用 joml-1.10.5 实测确认日志读数；baseRot 为弧度且 X/Y 取反（GeometryBone 解析 `toRadians(-x)`），snapRot 经 ToRadFunction 为弧度。

### 26.1 positionRider 数学（javap 确认）

`positionRider` = `getPassengerRidingPosition - getVehicleAttachmentPoint`；`getVehicleAttachmentPoint` 默认 AT_FEET（脚部）→ 乘客最终位置 = 模组返回的绝对值（`position + bonePos + offset`）。HMCL 环境与 dev runClient 存在行为差异（如 FeatureFlagUniverse 不一致致 EntityType.create 静默返回 null）。
